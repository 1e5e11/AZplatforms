# 墨页 · Markdown 显示器使用手册

一份可阅读、可分享，也能自己演示分页与目录的 Markdown 文档。

**规范版本：MD Viewer v1。** 本手册使用真实的目录、分页与翻页指令，共五页。在墨页中打开后，点击下方目录可以跨页跳转；在普通 Markdown 阅读器中，这些扩展注释不可见，正文仍然完整可读。

<!-- md:toc -->

## 1. 打开显示器

这是纯静态网页，Markdown 渲染与 PDF 生成全部在浏览器内完成，没有后端接口，也不需要安装 Node.js 或 npm 依赖。直接双击 `index.html`，即可编辑、打开本地文档并导出文字、矢量或图片 PDF；也可以把下方「部署时需要哪些文件」列出的文件部署到任意静态网站。

开发调试时，可以在项目目录运行可选的本地静态预览工具：

```sh
npm start
```

然后打开 [墨页编辑界面](http://localhost:4173/index.html)。仅这个开发预览命令需要 Node.js 20 或更高版本；网页运行与 PDF 导出均不依赖它。项目已经包含浏览器依赖，不必先安装 npm 包。

如果只想在自己的网页中使用 Markdown 显示能力，请阅读 [显示引擎接入文档](./MARKDOWN_ENGINE.md)。独立引擎位于 `md-renderer.js`，配套排版位于 `md-renderer.css`；当前编辑器本身也通过这套引擎渲染正文。

本地双击 HTML 可以编辑文字、打开本地文件并导出 PDF；从「文件地址」加载同目录文件时，请使用静态网站地址，因为浏览器会限制 `file://` 通过 `fetch` 读取其他本地文件。离线文档请使用「打开文件」或拖入。

### 编辑模式

- 在左侧的大尺寸编辑器中输入或粘贴 Markdown，标题、强调、链接、代码等语法会高亮；右侧自动预览。
- 点击编辑器标题栏中的「复制原文」，可直接复制完整 Markdown。
- 点击「打开文件」，或把 `.md` / `.markdown` 文件拖入页面。
- 点击「保存」或按 **Ctrl / Command + S**，将当前 Markdown 覆盖写回打开的本地文件。新文档、地址载入和传统文件导入会在首次保存时要求选择保存位置。
- 点击「另存为」或按 **Ctrl / Command + Shift + S**，选择新文件名和位置；保存成功后，后续「保存」写入该新文件。文件名旁的「未保存」标记只在成功写入后清除，关闭页面前会提示尚未保存的修改。
- 在导出格式中选择 **PDF、PNG、JPEG 或 HTML**，点击「导出全文」，下载完整文档，包含所有分页、目录、公式、高亮代码和图片。
- 选择 PDF 后，可在旁边指定 **文字 PDF、矢量 PDF 或图片 PDF**。默认文字模式，支持选择、复制和搜索；矢量模式将文字转为轮廓，放大保持清晰；图片模式沿用高清截图。
- 文档包含本地配图时，点击「打开文件夹」选择文档和图片所在的目录，保留子目录及相对路径；多份 Markdown 会出现文档选择框。
- 也可以把 Markdown 和图片一起拖入，或打开文档后点击「导入图片」。单独导入的图片按文件名匹配，重名时请用文件夹方式保留路径。
- 在「文件地址」中输入相对路径或远程原始文件地址，点击「载入」。
- 右侧目录包含全文标题，点击可以自动切换到目标页。
- 点击「复制 HTML」复制全文；快捷键是 Ctrl / Command + Enter。
- 点击「复制阅读链接」分享当前文档。接收者打开的是纯阅读模式。
- 点击「阅读规范」即可在预览中打开本手册。

### 纯阅读模式

只要 URL 中出现 `md` 或 `src`，就进入纯阅读模式。没有应用标题、工具栏、编辑器、侧栏或底部提示；页面仅包含排版后的文档。

只有作者写入的 `md:toc`、`md:nav` 才会在文档内部产生目录和翻页链接。没有这些指令，就不会额外添加目录和导航。代码块自带语言标签与复制按钮，这些是文档内部的操作，纯阅读模式不会因此显示应用工具栏。

试着打开 [本手册的纯阅读版](./index.html?src=README.md)，或 [现有的食材文件](./index.html?src=foods.md)。这些相对示例适用于手册与显示器放在同一目录的部署。

# URL 传入规范

## 2. 传入 Markdown 正文

参数 `md` 表示 UTF-8 Markdown **内容**。URL 不能直接携带一个操作系统文件对象；本地文件可以先用「打开文件」读取，再点击「复制阅读链接」，将内容编码到 URL。

查询参数示例：

```text
index.html?md=%23%20Hello%0A%0AHello%2C%20Markdown!
```

[打开这个正文示例](./index.html?md=%23%20Hello%0A%0AHello%2C%20Markdown!)

推荐用 `URLSearchParams` 自动编码，避免中文、换行、`&`、`#`、`+` 或 `%` 改变参数含义：

```javascript
const viewer = new URL('https://your-site.example/index.html');
const params = new URLSearchParams({
  md: '# 你好，Markdown\n\n中文、A&B、C++、100% 都可以传入。'
});
viewer.hash = params.toString();
console.log(viewer.href);
```

也支持 `#md=...` 片段形式。「复制阅读链接」默认使用片段，正文不会作为页面 HTTP 请求的查询参数发送给静态服务器，但它仍然存在于链接和浏览器历史中，不是加密或访问控制。

不要先 `encodeURIComponent()` 再交给 `URLSearchParams`，这会重复编码。若手动拼接，使用 `'?md=' + encodeURIComponent(markdown)` 即可。

## 3. 传入文件地址

参数 `src` 表示 Markdown **原始文件地址**，可以是 HTTP(S) 绝对地址或相对当前显示器页面的路径。

```text
index.html?src=foods.md
index.html?src=docs%2Fguide.md
index.html?src=https%3A%2F%2Fexample.com%2Fguide.md
```

构造远程链接：

```javascript
const viewer = new URL('https://your-site.example/index.html');
viewer.search = new URLSearchParams({
  src: 'https://content.example/docs/guide.md?version=2&lang=zh',
  page: '2'
}).toString();
console.log(viewer.href);
```

规则：

- 必须返回 Markdown 文本，不能是 GitHub 的文件预览网页；使用其 Raw 原始文件地址。
- 跨域源需要允许浏览器 CORS 访问；显示器不提供代理。
- HTTPS 页面应使用 HTTPS 文件源，以免被浏览器阻止混合内容。
- 不发送登录凭据，不接受地址中的账号密码，不支持 `file:`、`javascript:` 或 `data:` 文件源。
- 远程 Markdown 的相对图片和普通链接，以重定向后的文件地址为基准解析。
- 本地导入和 `md` 正文的相对资源以显示器页面地址为基准；不会读取电脑中的其他文件。
- 文件必须为 UTF-8，最大 2 MiB，远程请求最多等待 15 秒。

## 4. 参数约定

| 参数 | 值 | 作用 |
| --- | --- | --- |
| `md` | 编码后的正文 | 直接显示 Markdown，包括空正文 |
| `src` | 编码后的地址 | 获取 Markdown 文件，不能为空 |
| `page` | 从 `1` 开始的整数 | 选择页面，默认第一页；超过总页数显示末页 |
| `page` | `all` | 连续显示所有页面，适合全文阅读与打印 |
| `anchor` | 标题标识符 | 跳转到标题；非连续模式下优先于 `page` 切到标题所在页 |

`md` 和 `src` 互斥，同名参数不允许重复。所有参数必须与正文来源放在同一个查询串或同一个片段中；不要混合 `?src=...` 和 `#md=...`。未知参数忽略。传入来源后即使出错，也只在文档区域显示错误，不切回编辑器。

`?src=...#标题标识符` 也能作为文件阅读的初始锚点；使用 `anchor` 参数更统一，尤其适合片段携带正文的场景。

# 分页示例

## 5. 真正的分页

在需要分页的位置写下这一行，前后各留一个空行：

```markdown
<!-- md:page -->
```

显示器按照指令拆分文档，不根据屏幕高度或字数自动切页。第一页是文件开头，每遇到一次有效的分页指令增加一页。开头、结尾或连续的分页指令会保留空页，通常应避免这样写。

本手册上一页和这一页之间，就放置了一个真实的分页指令。

### 一个可复制的两页文件

下面整个代码块只是示例，不会被执行成分页：

```markdown
# 第一页

<!-- md:toc -->

## 开始

这是第一页的内容。

<!-- md:nav -->

<!-- md:page -->

# 第二页

## 继续阅读

这是第二页的内容。

<!-- md:nav -->
```

把代码块内容保存为 `guide.md`，通过 `index.html?src=guide.md` 打开，就得到可以翻页的纯文档。

### URL 选择页面

```text
index.html?src=README.md&page=3
index.html?src=README.md&page=all
```

[直接打开本手册第三页](./index.html?src=README.md&page=3) · [连续阅读整本手册](./index.html?src=README.md&page=all)

`page=0`、负数、小数和非数字值会显示参数错误。切页会更新纯阅读链接，浏览器的前进、后退可以恢复之前的阅读位置。

## 6. 文内翻页链接

在希望出现翻页导航的地方插入：

```markdown
<!-- md:nav -->
```

这个位置会生成「上一页 / 页码 / 下一页」。第一页没有上一页，末页没有下一页，单页文档不显示翻页内容。每一页需要导航时都要写这个指令，不会自动重复到其他页。

纯阅读模式严格保留作者选择：不写 `md:nav` 就不添加翻页控件。此时仍可以通过 `page` 参数、目录或标题链接访问其他页，也可以使用 `page=all`。

### 标题标识符

标识符根据标题的纯文本生成：拉丁字母转小写，保留 Unicode 字母、数字、下划线和连字符，移除其他标点，空白变为 `-`。中文可以直接作为标识符。空标识符使用 `section`。

同名标题在全文中去重，追加 `-2`、`-3` 等后缀；若这些标识符已经被使用，则继续递增，直至唯一。

| 标题 | 标识符 |
| --- | --- |
| `## Hello World` | `hello-world` |
| `## 中文标题` | `中文标题` |
| 再次出现 `## 中文标题` | `中文标题-2` |

Markdown 内可以写 `[跳到介绍](#hello-world)`。显示器会自动查找目标标题并跨页跳转。URL 可以写 `?src=guide.md&anchor=hello-world`。

## 8. 指令的精确语法

三个指令区分大小写，只接受以下形式：

```markdown
<!-- md:page -->

<!-- md:toc -->

<!-- md:nav -->
```

每条指令必须独占一行、从行首开始，前后各空一行（文件开头或结尾除外），位于文档顶层。行末空白允许。缩进、代码块、行内代码、列表、引用和 HTML 容器内部的注释不会解释为扩展指令。

普通 `---` 仍是水平分隔线，如下所示，**不会分页**：

---

引用中的指令不会执行：

> 这是一段引用。
>
> `<!-- md:page -->`

不认识的注释按普通 HTML 注释处理，不产生界面元素。这三个指令不修改 Markdown 标准，它们是墨页在顶层 HTML 注释上增加的兼容扩展。

# 常用排版与常见问题

## 9. Markdown 排版示例

普通文字、**粗体**、*斜体*、~~酒红色删除线~~，以及 `行内代码`。

- 列表第一项
- 列表第二项
  - 嵌套列表

1. 打开文件
2. 检查预览
3. 分享阅读链接

- [x] 支持任务列表
- [ ] 写下下一段内容

> 引用适合提示、摘录或补充说明。

```javascript
const markdown = '# 你好\n\n一份简单的文档。';
const url = new URL('https://your-site.example/index.html');
url.hash = new URLSearchParams({ md: markdown }).toString();
```

| 功能 | 普通模式 | URL 纯阅读模式 |
| --- | --- | --- |
| Markdown 正文与 LaTeX 公式 | 支持 | 支持 |
| 全文侧栏目录 | 自动生成 | 不显示 |
| 文内目录 | 写 `md:toc` | 写 `md:toc` |
| 底部工具翻页 | 多页时显示 | 不显示 |
| 文内翻页 | 写 `md:nav` | 写 `md:nav` |
| 编辑、导入和分享 | 支持 | 不显示 |

图片写法为 `![说明](./images/example.png)`，也支持引用式图片和 HTML 的 `<img>`。远程文件中的相对图片地址会跟随文件所在目录；本地文件请同时导入配图，浏览器不会自动读取磁盘上的相邻文件。

图片支持 PNG、JPEG、GIF、WebP、AVIF、BMP、ICO 和 SVG，并支持这些格式的 Base64 `data:image/...` 内嵌图片。单张导入图片最多 10 MiB，总计最多 20 MiB。图片按比例缩放到正文宽度。「复制 HTML」会内嵌本地图片，不依赖原电脑的文件路径。小图片也能随阅读链接分享；正文及图片编码后的链接仍受 64,000 字符上限限制，较大的文档可以复制 HTML，或将 Markdown 和图片一起托管后使用 `src` 分享。

阅读链接可带可选的 `base`（正文中相对资源的基准地址）和 `images`（JSON 格式的 `[资源绝对地址, 图片 data URL]` 数组）参数；应用会自动生成，原有 `md` / `src` 链接保持兼容。图片仅在内存中处理，选择文件夹不会上传文件。

代码使用等宽字体；其余正文使用 Times New Roman / 宋体。

### LaTeX 数学公式

编辑预览、纯阅读链接和打印都支持 LaTeX 公式，公式由随项目本地部署的 KaTeX 渲染，不依赖外部 CDN。

行内公式可以使用 `$...$` 或 `\(...\)`：

```markdown
质能方程是 $E=mc^2$，勾股定理是 \(a^2+b^2=c^2\)。
```

独立公式可以使用 `$$...$$` 或 `\[...\]`，定界符可以分行书写：

```markdown
$$
\int_{-\infty}^{\infty} e^{-x^2}\,dx = \sqrt{\pi}
$$
```

代码围栏和行内代码中的美元符号不会解释为公式。普通正文需要显示美元符号时可以写成 `\$`。不合法的 LaTeX 会以酒红色原文提示显示，不会中断整篇文档的排版。

没有定界符的裸 LaTeX 也会自动识别，适合直接粘贴聊天工具或网页里的公式：

```markdown
设
\zeta_n=e^{2\pi i/n},
则本原 n 次单位根为
\zeta_n^k,\qquad 1\le k\le n,\ \gcd(k,n)=1.
```

整行公式按独立公式显示，句子中夹带的公式按行内公式显示。只有 KaTeX 能完整解析的片段才会转换，无法解析的写法（例如未知命令或 Windows 路径）保持原文；代码块、行内代码以及已经用 `$...$`、`\(...\)` 写好的公式不会被重复处理。从网页复制时常见缺失的 `\substack` 内换行 `\\` 和对齐环境行首的 `[2mm]` 间距会自动补回。

被压平成一行、两列（编号 + 公式）的表格文本也会自动还原成表格，例如 `n \Phi_n(x) 1 x-1 2 x+1 …` 会显示为「n / Φ_n(x)」两列表格，公式单元格照常渲染。

### 多语言代码高亮与复制

在代码围栏的三个反引号后写语言名称，即可高亮。每个代码块右上角都有「复制」按钮，点击只复制代码正文，保留换行和缩进，不包含语言标签、按钮文字或 Markdown 围栏。编辑预览和 URL 纯阅读模式都支持，复制成功后按钮短暂显示「已复制」。

支持 `cpp` / `c++`、`python` / `py`、`java`、`javascript` / `js`、`html`、`css`、`markdown` / `md`，以及 C、TypeScript、JSON、SQL、Bash、Go、Rust、YAML 等常见语言。未声明语言或不支持的语言按纯文本显示，仍然可以复制；单个代码块超过 100,000 字符时也按纯文本显示，以避免长时间高亮计算。不会猜测未标注代码的语言。

```cpp
#include <iostream>
int main() {
    std::cout << "Hello, C++!" << std::endl;
    return 0;
}
```

```python
def greet(name: str) -> str:
    return f"你好，{name}！"

print(greet("Markdown"))
```

```java
public class Hello {
    public static void main(String[] args) {
        System.out.println("Hello, Java!");
    }
}
```

```javascript
const languages = ["C++", "Python", "JavaScript"];
languages.forEach(name => console.log(`Hello, ${name}!`));
```

```html
<article class="note">
  <h1>Hello, HTML!</h1>
  <a href="https://example.com">打开网页</a>
</article>
```

```css
.note {
  color: #7c0a21;
  padding: 16px;
  font-family: "Times New Roman", serif;
}
```

```md
# Markdown 示例

**重点**、*斜体*、[网页链接](https://example.com)。

<!-- md:page -->
```

上面代码块里的 HTML、JavaScript 和分页指令只作代码显示，不会执行或改变当前文档。剪贴板被浏览器限制时，会尝试兼容复制；仍失败则显示选中的原文供手动复制，按 Escape 关闭。

### 点击链接跳转网页

使用 `[链接文字](https://example.com)`、`<https://example.com>`，或直接写 `https://example.com`。以下是可以点击的实际示例：

- [打开示例网页](https://example.com)
- <https://example.com>
- https://example.com

HTTP(S) 网页链接在新标签页打开，保留当前文档位置；相对网页链接以 Markdown 文件地址为基准解析。`[跳到手册首页](#墨页-markdown-显示器使用手册)` 这样的标题链接则在文档内定位，必要时自动翻页。代码块中的 URL 保持原样，不自动变成链接。

「复制 HTML」导出时保留高亮颜色，并移除需要应用脚本的代码复制按钮；粘贴到其他网页时不必引入 Highlight.js。

## 10. 常见问题

### 为什么远程地址打不开？

先确认它返回原始 Markdown，而不是网页。远程站点必须允许跨域请求；私有仓库或需要登录的链接不会携带登录凭据。可以下载文件后本地打开，或把文件放到与显示器同源的静态目录。

### 文件链接必须以 .md 结尾吗？

远程地址不强制扩展名，接口只要返回 UTF-8 Markdown 文本即可。若服务器声明返回 HTML，会提示改用原始文件链接。本地文件选择限制为 `.md` / `.markdown`。

### 为什么目录或分页没生效？

检查大小写、空格、独立行和前后空行。指令不能放在代码块、引用或列表内部。先把本手册第三页的两页示例原样复制到编辑器验证。

### 很长的文档怎么分享？

不同浏览器、聊天软件和服务器对 URL 长度限制不同。正文模式适合短文；复制功能拒绝超过 64,000 字符的链接，这不是跨平台长度保证。长文应托管为文件，用 `src` 分享。

### HTML 会执行脚本吗？

不会有意执行文档中的脚本。Markdown 渲染结果经过 DOMPurify 清理，禁用脚本、事件属性、内联样式、表单和嵌入内容，并限制资源协议。保留基本文本排版、表格和图片。外部图片仍可能发起网络请求。

### 导出和打印如何处理分页？

「导出全文」与「复制 HTML」包含全部页面，目录链接改为全文内的锚点，交互翻页和代码复制按钮移除，不影响当前预览的页码。

- PDF 为 A4 白底排版，`md:page` 开始新页；超过一张纸的内容继续分页，尽量避开文字行、图片、公式和表格行。三种内容模式均包含全文，不改变当前预览的页码。
- **文字 PDF（默认）**：正文与代码写入可选择、复制和搜索的文字对象，嵌入字体；中文正文使用随项目部署的 Noto Serif SC，`**粗体**` 使用真实粗体字形，公式保留 KaTeX 字形。复杂公式复制后的顺序由 PDF 阅读器决定，不等同于 LaTeX 源码。
- **矢量 PDF**：文字及 SVG 标签转为字形轮廓，线条、表格和 SVG 配图保留路径，放大保持清晰；转为轮廓的文字无法选择、复制或搜索。
- **图片 PDF**：将每一页排版截图保存为高清位图，保留现有导出效果；文字无法选择或搜索，放大后受图片分辨率限制。
- 原文中的 PNG、JPEG 等位图在文字与矢量 PDF 中仍是位图，不会自动描摹成矢量图；SVG 配图中的标签按图形轮廓保存。PDF 字体与转换库从本地 `vendor/` 加载，运行时无需连接外部 CDN。字体通过按需加载的静态脚本 `vendor/pdf-fonts.js` 与 `vendor/pdf-fonts-bold.js` 提供；粗体脚本只在需要时加载。双击 `file://` 页面也能使用三种 PDF 模式，不需要启动任何服务。
- PNG 与 JPEG 为白底全文长图，宽 1,792 像素。超长文档达到浏览器画布限制时会提示改用 PDF，或拆分文档导出。
- HTML 文件内嵌排版、代码颜色、公式字体及图片，可离线打开，并保留打印分页样式；无需额外复制 vendor 文件。
- 远程图片需要允许跨域访问。无法读取或损坏的图片会阻止导出并给出提示，导入本地图片后可重新导出。

直接从浏览器打印当前页面时，先打开 `page=all`，确保所有页都在文档中。

### 为什么保存不能覆盖原文件？

直接覆盖需要浏览器的文件系统访问能力。请在 Chrome / Edge 中，通过「打开文件」、支持的文件拖入或「打开文件夹」选择原文档，并在 HTTPS 页面或 `localhost` / `127.0.0.1` 本地预览中使用。首次写入可能需要浏览器授予权限。

不支持该能力的浏览器会下载 Markdown 副本，并明确提示无法覆盖原文件；下载副本不会清除「未保存」标记。通过 URL 载入的文档会另选本地保存位置。保存与另存为只写入 Markdown 原文，配图仍需保留在原文引用的相对目录中。

### 部署时需要哪些文件？

保留 `index.html`、`styles.css`、`app.js`、`md-images.js`、`md-files.js`、`md-export.js`、`md-pdf.js`、`md-renderer.js`、`md-renderer.css`、整个 `vendor/`，以及需要公开阅读的 Markdown 和图片。以 `index.html` 作为入口，静态主机可把它配置为默认首页。`server.cjs` 只用于本地预览，监听 `127.0.0.1:4173`。

静态部署不需要 `server.cjs`、`package.json`、`package-lock.json`、`node_modules/`、`scripts/` 或 `tests/`。预生成的字体脚本随 `vendor/` 一起复制即可，无需在运行时构建。

### 开发与依赖

运行 `npm run check` 检查脚本语法。`package-lock.json` 固定依赖版本，`vendor/` 中包含 marked 18.0.12、DOMPurify 3.4.15、Highlight.js 11.12.0、KaTeX 0.18.7、html2canvas 1.4.1、jsPDF 4.2.1、opentype.js 1.3.4、svg2pdf.js 2.8.1 的浏览器文件、公式字体、Noto Serif SC 常规字体与许可证，页面运行时无需连接 CDN。

安装开发依赖后运行 `npm test`，使用本机 Edge 执行保存与导出回归测试，包括覆盖保存、另存为、取消和写入失败、异步写入、文件夹和拖入句柄，以及真实 PDF / PNG / JPEG / HTML 下载。PDF 内容测试使用 PDF.js 检查中文文字、字形路径、页图、分页完整性、字体错误恢复与 SVG / 位图配图，并直接打开本地 `file://` 页面、禁止 HTTP(S) 请求，验证三种 PDF 模式无需任何服务。其他系统可在 `playwright.config.cjs` 中调整浏览器通道。

启动本地服务后可打开 [图片回归测试](./tests/images.html)。测试使用临时内存文件验证本地图片、文件夹路径、导出、阅读链接和公式兼容性，页面末尾显示 `SUCCESS` 时通过全部检查。

本项目 UI 遵循 `skills/azhs-ui-design/SKILL.md`：白色底面、酒红柔光、宋体/Times New Roman、微圆角与紧凑透明面板。其他系统若缺少这些字体，会使用衬线回退字体。
